# 결재

한국 SI 시스템 사실상 필수 도메인. 거의 모든 비즈니스 도메인이 결재 라인을 태우거나
승인 프로세스를 거친다. 순차/병렬/혼합 결재 라인을 지원하며, 모든 단계와 이력을
RO 패턴으로 보존하여 감사 추적성을 확보한다.

## entities (시드)

### approval_request
```yaml
type: entity
name: approval_request
display: 결재 요청
domain: [결재]
table: approval_request
status: draft
pattern: D2
columns:
  - { name: id,           type: bigserial,    pk: true,  nullable: false }
  - { name: template_id,  type: bigint,       nullable: false }
  - { name: title,        type: varchar(200), nullable: false }
  - { name: requester_id, type: bigint,       nullable: false }   # app_user.id
  - { name: request_type, type: varchar(60),  nullable: false }   # 공통코드 REQUEST_TYPE 참조
  - { name: status,       type: varchar(30),  nullable: false, default: 'DRAFT' }  # DRAFT/SUBMITTED/IN_PROGRESS/APPROVED/REJECTED/CANCELLED
  - { name: current_step, type: int,          nullable: false, default: 0 }
  - { name: payload,      type: text,         nullable: true }    # 도메인별 폼 데이터 (JSON 직렬화)
  - { name: submitted_at, type: timestamptz,  nullable: true }
  - { name: completed_at, type: timestamptz,  nullable: true }
  - { name: created_at,   type: timestamptz,  nullable: false, default: now() }
indexes:
  - { name: ix_approval_request_template,    columns: [template_id] }
  - { name: ix_approval_request_requester,   columns: [requester_id] }
  - { name: ix_approval_request_status,      columns: [status] }
  - { name: ix_approval_request_submitted,   columns: [submitted_at] }
workflow:
  status_column: status
  states: [DRAFT, SUBMITTED, IN_PROGRESS, APPROVED, REJECTED, CANCELLED]
  transitions:
    - { action: submit,  from: [DRAFT],                            to: SUBMITTED }
    - { action: start,   from: [SUBMITTED],                        to: IN_PROGRESS }
    - { action: approve, from: [IN_PROGRESS],                      to: APPROVED }
    - { action: reject,  from: [IN_PROGRESS],                      to: REJECTED }
    - { action: cancel,  from: [DRAFT, SUBMITTED, IN_PROGRESS],    to: CANCELLED }
```

### approval_line
```yaml
type: entity
name: approval_line
display: 결재 라인
domain: [결재]
table: approval_line
status: draft
pattern: MD
columns:
  - { name: id,             type: bigserial,    pk: true,  nullable: false }
  - { name: request_id,     type: bigint,       nullable: false }
  - { name: step_no,        type: int,          nullable: false }   # 1, 2, 3 ... 동일 step_no = 병렬
  - { name: approver_id,    type: bigint,       nullable: false }   # app_user.id
  - { name: approval_type,  type: varchar(20),  nullable: false, default: 'SEQUENTIAL' }  # SEQUENTIAL/PARALLEL/REFERENCE
  - { name: status,         type: varchar(20),  nullable: false, default: 'PENDING' }      # PENDING/APPROVED/REJECTED/SKIPPED/RETURNED
  - { name: approved_at,    type: timestamptz,  nullable: true }
  - { name: comment,        type: varchar(1000), nullable: true }
  - { name: delegated_from, type: bigint,       nullable: true }   # 위임받은 경우 원 결재자
indexes:
  - { name: ix_approval_line_request,            columns: [request_id] }
  - { name: ix_approval_line_approver,           columns: [approver_id] }
  - { name: ux_approval_line_request_step_user,  columns: [request_id, step_no, approver_id], unique: true }
  - { name: ix_approval_line_status,             columns: [status] }
workflow:
  status_column: status
  states: [PENDING, APPROVED, REJECTED, SKIPPED, RETURNED]
  transitions:
    - { action: approve, from: [PENDING],            to: APPROVED }
    - { action: reject,  from: [PENDING],            to: REJECTED }
    - { action: skip,    from: [PENDING],            to: SKIPPED }   # 위임/비활성 시 자동 스킵
    - { action: return,  from: [PENDING, APPROVED],  to: RETURNED }  # 회수/반려
```

## rules (시드 비즈니스 규칙)
- `approval_request.status` 는 상태머신: DRAFT → SUBMITTED → IN_PROGRESS → (APPROVED | REJECTED | CANCELLED). 임의 전이 금지
- `approval_request.payload` 는 양식별 폼 데이터 — 스키마 검증은 `approval_template.request_type` 기준으로 응용 레이어가 수행
- `approval_line.step_no` 동일 값은 병렬 결재 — 동일 step 모든 라인 APPROVED 시 다음 step 진행
- `approval_line.approval_type=REFERENCE` 는 합의/참조 — 승인 의무 없음, 단 통지는 발송
- 결재 진행 중 결재자 비활성/퇴사 시 `delegated_from` 로 위임 이력 보존 — 원 결재자 추적 가능
- `approval_history` 는 RO — 모든 액션(SUBMIT/APPROVE/REJECT/CANCEL/RETURN/DELEGATE) append-only. 수정 UI 노출 금지
- 결재 라인의 hard delete 금지 — 회수/반려는 `status=RETURNED` + history 적재
- `template.is_system=true` 양식은 boot 시 보장, UI 삭제 불가 (예: 기본 휴가신청/구매요청 등)
- `is_active=false` 양식은 신규 요청 생성 불가, 기 요청은 진행 가능 (양식 deprecate 패턴)
- 결재 통지는 [[알림]] 도메인의 notification 으로 발송 — 라인 PENDING 진입 시 approver_id 에게 이벤트 발행
- 결재 상태 코드(`status`, `action_type`, `approval_type`) 는 [[공통코드]] 의 code 그룹(APPROVAL_STATUS, APPROVAL_ACTION, APPROVAL_TYPE) 참조 권장
- `approval_line` 상태 전이도 `workflow` 블록(`approve`/`reject`/`skip`/`return`) 가드로 강제 (Stage 3 자동 생성). 직접 UPDATE 금지 — `approval_history` 적재와 함께 워크플로 서비스 호출
