# 배송관리

주문 출고 이후의 물류 단계를 다루는 도메인. [[주문관리]] 와 자연스럽게 연결되며
(분할배송 시 N:1), 자체 상태머신(pending→picked→in_transit→delivered)을 보유한다.
모든 추적 이벤트는 RO 패턴으로 append-only 보존하여 분쟁 추적성을 확보한다.

```yaml
  - { name: ix_courier_code, columns: [code], unique: true }
```

### delivery
```yaml
type: entity
name: delivery
display: 배송
domain: [배송관리]
table: delivery
status: draft
pattern: MD   # 배송 마스터 + tracking/items 그리드
columns:
  - { name: id,                type: bigserial,    pk: true,  nullable: false }
  - { name: sales_order_id,    type: bigint,       nullable: true }                  # 주문이 없는 배송도 허용 (샘플 발송 등)
  - { name: courier_id,        type: bigint,       nullable: false }
  - { name: tracking_no,       type: varchar(60),  nullable: true }                  # courier 발급 후 채워짐
  - { name: recipient_name,    type: varchar(100), nullable: false }
  - { name: recipient_phone,   type: varchar(40),  nullable: false }
  - { name: address_line1,     type: varchar(200), nullable: false }
  - { name: address_line2,     type: varchar(200), nullable: true }
  - { name: postal_code,       type: varchar(20),  nullable: false }
  - { name: status,            type: varchar(20),  nullable: false, default: 'pending' }
  - { name: estimated_at,      type: timestamptz,  nullable: true }
  - { name: shipped_at,        type: timestamptz,  nullable: true }
  - { name: delivered_at,      type: timestamptz,  nullable: true }
  - { name: created_at,        type: timestamptz,  nullable: false, default: now() }
indexes:
  - { name: ix_delivery_order,    columns: [sales_order_id] }
  - { name: ix_delivery_courier,  columns: [courier_id] }
  - { name: ix_delivery_status,   columns: [status] }
  - { name: ux_delivery_tracking, columns: [courier_id, tracking_no], unique: true }
workflow:
  status_column: status
  states: [pending, picked, in_transit, delivered, failed, returned]
  transitions:
    - { action: pick,    from: [pending],                    to: picked }
    - { action: ship,    from: [picked],                     to: in_transit }
    - { action: deliver, from: [in_transit],                 to: delivered }
    - { action: fail,    from: [picked, in_transit],         to: failed }   # 배송실패(부재/주소오류)
    - { action: returnp, from: [in_transit, delivered, failed], to: returned }  # 반품 회수
```

## rules (시드 비즈니스 규칙)
- 1 [[주문관리]] 주문 = 1 또는 N 배송 (분할배송 허용). 주문 없이도 배송 가능 (`sales_order_id` nullable)
- 배송 상태머신: `pending → picked → in_transit → delivered`. 실패 시 `failed`, 반품은 `returned`
- 상태 전이는 `workflow` 블록(`pick`/`ship`/`deliver`/`fail`/`returnp`) 가드에 의해 강제 (Stage 3 자동 생성). 직접 UPDATE 금지
- `delivery_tracking` 은 RO append-only — 모든 추적 이벤트(PICKED_UP/SCANNED/OUT_FOR_DELIVERY/DELIVERED/FAILED/RETURNED) 보존
- `courier.is_active=false` 면 신규 delivery 생성 불가 (기존 delivery 진행은 가능 — deprecate 패턴)
- `tracking_no` 는 (courier_id, tracking_no) 조합으로 unique. 같은 courier 내 중복 발급 방지
- 배송 상태 전환 시 [[알림]] 도메인의 notification 으로 수령인에게 SMS/푸시 발송 권장
- `courier.code` 는 [[공통코드]] 의 `COURIER_CODE` 그룹과 동기화 권장 (UI 드롭다운 일관성)
