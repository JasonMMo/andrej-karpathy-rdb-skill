## rules (시드 비즈니스 규칙)
- (year, month) 조합은 fiscal_period에서 유일
- 분개 1행은 debit 또는 credit 중 하나만 0이 아니어야 함 (CHECK 제약 검토)
- 마감된(closed_at is not null) period에는 ledger_entry 추가 금지
- journal_entry 1건의 모든 ledger_entry 차변 합 = 대변 합 (double-entry invariant; 응용단에서 강제)
- journal_entry.total_debit / total_credit 은 소속 ledger_entry 집계와 일치 (post 시 재계산)
- journal_entry.status = 'posted' 이후 ledger_entry 변경 금지 (reversed 처리로만 정정)

## verified (실 DB 검증 — Growth-26 E2E)

v5에서 Stage 1→2→3 산출 schema.sql 을 HSQLDB 인메모리 DB에 실제로 실행해 다음을 증명:

- **Schema apply** — V001~V004(CREATE TABLE / INDEX / FK) 전 SQL이 HSQLDB pgs 모드에서 정상 컴파일 (account / fiscal_period / journal_entry / ledger_entry 4개 + FK 5개)
- **Double-entry invariant** — `SUM(ledger_entry.debit) = SUM(ledger_entry.credit)` per journal_entry 가 실제로 성립 (현금 100,000 / 매출 100,000 분개 1건으로 검증)
- **ON DELETE CASCADE** — journal_entry DELETE → 소속 ledger_entry 자동 소멸 (`ledger-belongs-to-journal` concept이 약속한 동작)
- **ON DELETE RESTRICT** — 참조된 fiscal_period DELETE 시도 → SQLSTATE 23504 로 차단 (`journal-belongs-to-period` concept이 약속한 동작)

다음 프로젝트가 이 seed로 시작할 때, 위 4개 제약은 **DDL 계약이 빈말이 아니라 실제 RDB에서 작동함이 검증된 보증**으로 간주해도 됨. 재검증은 dialect 변경(postgres/mysql) 시에만 필요.
