# 파일관리

게시판 첨부, 결재 첨부, 사용자 프로필 사진 등 모든 도메인의 binary asset 을
단일 도메인으로 수렴. storage_type 어댑터(LOCAL/S3/AZURE)로 백엔드 추상화,
file_folder 트리 구조로 조직 정렬, file_acl 로 RBAC 와 결합한 세밀한 접근 제어.

## entities (시드)

### file_folder
```yaml
type: entity
name: file_folder
display: 폴더
domain: [파일관리]
table: file_folder
status: draft
pattern: TR
columns:
  - { name: id,          type: bigserial,    pk: true,  nullable: false }
  - { name: parent_id,   type: bigint,       nullable: true }    # null = 최상위
  - { name: name,        type: varchar(200), nullable: false }
  - { name: owner_id,    type: bigint,       nullable: false }   # app_user.id
  - { name: is_system,   type: boolean,      nullable: false, default: false }  # 도메인 예약 폴더 (예: /approval/{request_id})
  - { name: created_at,  type: timestamptz,  nullable: false, default: now() }
indexes:
  - { name: ix_file_folder_parent,         columns: [parent_id] }
  - { name: ix_file_folder_owner,          columns: [owner_id] }
  - { name: ux_file_folder_parent_name,    columns: [parent_id, name], unique: true }
```

### file
```yaml
type: entity
name: file
display: 파일
domain: [파일관리]
table: file
status: draft
pattern: D2
columns:
  - { name: id,             type: bigserial,    pk: true,  nullable: false }
  - { name: folder_id,      type: bigint,       nullable: true }    # null = 폴더 미지정 (도메인 직접 참조)
  - { name: original_name,  type: varchar(255), nullable: false }
  - { name: stored_name,    type: varchar(255), nullable: false }   # UUID 또는 hash-based, 충돌 방지
  - { name: mime_type,      type: varchar(120), nullable: false }
  - { name: size_bytes,     type: bigint,       nullable: false }
  - { name: checksum,       type: varchar(64),  nullable: true }    # SHA-256 hex
  - { name: storage_type,   type: varchar(20),  nullable: false, default: 'LOCAL' }  # LOCAL/S3/AZURE/GCS
  - { name: storage_path,   type: varchar(500), nullable: false }   # 키/경로 (provider 별 의미)
  - { name: uploader_id,    type: bigint,       nullable: false }   # app_user.id
  - { name: ref_domain,     type: varchar(60),  nullable: true }    # 참조 도메인 (예: 게시판/결재) — 역추적 단서
  - { name: ref_id,         type: bigint,       nullable: true }    # 참조 entity id (느슨한 polymorphic FK)
  - { name: is_deleted,     type: boolean,      nullable: false, default: false }  # soft delete
  - { name: deleted_at,     type: timestamptz,  nullable: true }
  - { name: uploaded_at,    type: timestamptz,  nullable: false, default: now() }
indexes:
  - { name: ix_file_folder,         columns: [folder_id] }
  - { name: ix_file_uploader,       columns: [uploader_id] }
  - { name: ix_file_checksum,       columns: [checksum] }  # 중복 업로드 탐지
  - { name: ix_file_ref,            columns: [ref_domain, ref_id] }
  - { name: ix_file_is_deleted,     columns: [is_deleted] }
```

### file_acl
```yaml
type: entity
name: file_acl
display: 파일 접근 권한
domain: [파일관리]
table: file_acl
status: draft
pattern: MD
columns:
  - { name: id,             type: bigserial,    pk: true,  nullable: false }
  - { name: file_id,        type: bigint,       nullable: false }
  - { name: principal_type, type: varchar(10),  nullable: false }   # USER/ROLE/PUBLIC
  - { name: principal_id,   type: bigint,       nullable: true }    # USER→app_user.id, ROLE→role.id, PUBLIC→null
  - { name: permission,     type: varchar(20),  nullable: false }   # READ/WRITE/DELETE/SHARE
  - { name: granted_at,     type: timestamptz,  nullable: false, default: now() }
  - { name: granted_by,     type: bigint,       nullable: true }    # app_user.id
  - { name: expires_at,     type: timestamptz,  nullable: true }    # 임시 공유 링크 지원
indexes:
  - { name: ix_file_acl_file,                              columns: [file_id] }
  - { name: ix_file_acl_principal,                         columns: [principal_type, principal_id] }
  - { name: ux_file_acl_file_principal_perm,               columns: [file_id, principal_type, principal_id, permission], unique: true }
  - { name: ix_file_acl_expires,                           columns: [expires_at] }
```

## rules (시드 비즈니스 규칙)
- 물리 파일 저장은 `storage_type` 어댑터가 위임 — DB는 메타데이터만 보유. 어댑터 신규 추가는 [[backend-contract]] 패턴 따름
- `stored_name` 은 절대 사용자 입력 사용 금지 — UUID/hash 기반 생성. `original_name` 만 표시용
- `checksum` 동일 + `size_bytes` 동일 = 중복 후보 — dedup 정책은 응용 결정(공유 vs. 새 row + 동일 storage_path)
- soft delete (`is_deleted=true`) 가 기본 — 물리 삭제는 retention 잡(예: 30일 grace) 후 `storage_type` 어댑터 호출로 실파일 제거
- `file_acl` 평가 우선순위: USER > ROLE > PUBLIC. 같은 principal 내에서는 명시적 DENY 컬럼 없이 grant 부재 = deny
- `principal_type=PUBLIC` 은 anonymous 공유 — 반드시 `expires_at` 강제 (응용 레이어 검증)
- `ref_domain` + `ref_id` 는 느슨한 polymorphic FK — 물리 FK 강제 안 함, 도메인별 정합성은 응용 보장. 강제하면 [[권한관리]]/[[게시판]]/[[결재]] 등 cross-domain FK 폭발
- `file_access_log` 는 RO append-only — 감사/통계용. 보존 정책 1년 권장
- `folder.is_system=true` 폴더는 도메인 자동 생성/삭제 (예: 결재요청 생성 시 `/approval/{request_id}` 자동 mkdir) — 사용자 UI 삭제 차단
- 폴더 트리 깊이 제한은 응용 정책(권장 ≤ 10) — DB 제약 대신 application validation
- mime_type allowlist/blocklist 은 응용 정책 — DB 는 저장만, 업로드 게이트가 차단
- 권한 검사는 [[권한관리]] 의 app_user → role → role_permission 흐름과 file_acl 의 AND 조건 — 어느 한쪽 통과로는 부족
