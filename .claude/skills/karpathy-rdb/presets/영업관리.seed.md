# 영업관리

CRM (Customer Relationship Management) — 영업 파이프라인. 잠재고객(lead) →
영업기회(opportunity) → 활동 이력(sales_activity)을 추적하며, 고객사 측
담당자(contact_person)를 함께 관리한다.

기존 도메인과의 연계:
- 고객관리(customer): opportunity·contact_person이 customer에 FK
- 권한관리(app_user): owner_user_id로 영업담당자 RBAC와 직결
- 주문관리(sales_order): opportunity가 won 상태로 마감되면 후속으로
  sales_order가 생성되지만 그 변환은 서비스 계층 책임(스키마 의존 없음)

## entities (시드)

### lead
```yaml
type: entity
name: lead
display: 잠재고객
domain: [영업관리]
table: lead
status: draft
pattern: L2  # list-detail — 영업담당자가 lead 목록에서 상세로 진입
columns:
  - { name: id,             type: bigserial,    pk: true,  nullable: false }
  - { name: company_name,   type: varchar(200), nullable: false }
  - { name: contact_name,   type: varchar(100), nullable: false }
  - { name: email,          type: varchar(255), nullable: true }
  - { name: phone,          type: varchar(30),  nullable: true }
  - { name: source,         type: varchar(30),  nullable: true }     # web|referral|event|cold
  - { name: status,         type: varchar(20),  nullable: false, default: 'new' }
  - { name: owner_user_id,  type: bigint,       nullable: true }     # → 권한관리.app_user
  - { name: created_at,     type: timestamptz,  nullable: false, default: now() }
  - { name: converted_at,   type: timestamptz,  nullable: true }
indexes:
  - { name: ix_lead_status, columns: [status] }
  - { name: ix_lead_owner,  columns: [owner_user_id] }
  - { name: ix_lead_email,  columns: [email] }
workflow:
  status_column: status
  states: [new, contacted, qualified, converted, lost]
  transitions:
    - { action: contact,   from: [new],                  to: contacted }
    - { action: qualify,   from: [contacted],            to: qualified }
    - { action: convert,   from: [qualified],            to: converted }
    - { action: lose,      from: [new, contacted, qualified], to: lost }
```

### opportunity
```yaml
type: entity
name: opportunity
display: 영업기회
domain: [영업관리]
table: opportunity
status: draft
pattern: MD  # master-detail — opportunity 상세 + sales_activity 자식 그리드
columns:
  - { name: id,                type: bigserial,    pk: true,  nullable: false }
  - { name: lead_id,           type: bigint,       nullable: true }  # 일부는 lead 없이 직접 생성
  - { name: customer_id,       type: bigint,       nullable: false } # → 고객관리.customer
  - { name: contact_person_id, type: bigint,       nullable: true }
  - { name: owner_user_id,     type: bigint,       nullable: false } # → 권한관리.app_user
  - { name: title,             type: varchar(255), nullable: false }
  - { name: stage,             type: varchar(20),  nullable: false, default: 'qualification' }
  - { name: expected_amount,   type: numeric(14,2), nullable: false, default: 0 }
  - { name: probability,       type: int,          nullable: false, default: 10 }  # 0~100
  - { name: expected_close_at, type: date,         nullable: true }
  - { name: closed_at,         type: timestamptz,  nullable: true }
  - { name: created_at,        type: timestamptz,  nullable: false, default: now() }
indexes:
  - { name: ix_opportunity_customer, columns: [customer_id] }
  - { name: ix_opportunity_owner,    columns: [owner_user_id] }
  - { name: ix_opportunity_stage,    columns: [stage] }
  - { name: ix_opportunity_lead,     columns: [lead_id] }
workflow:
  status_column: stage
  states: [qualification, proposal, negotiation, won, lost]
  transitions:
    - { action: propose,   from: [qualification],            to: proposal }
    - { action: negotiate, from: [proposal],                 to: negotiation }
    - { action: win,       from: [proposal, negotiation],    to: won }
    - { action: lose,      from: [qualification, proposal, negotiation], to: lost }
```

## rules (시드 비즈니스 규칙)

- lead 상태 enum: `new|contacted|qualified|converted|lost`. workflow 가드로 전이 강제
- lead → opportunity 변환 시: lead.status=converted, lead.converted_at=now(),
  opportunity.lead_id에 원 lead.id 기록 (추적용). 변환 후 lead는 보존(삭제 안 함)
- opportunity stage enum: `qualification|proposal|negotiation|won|lost`. workflow 가드 강제
- opportunity.probability는 0~100 (Stage 3 validator). stage별 기본값
  (qualification=10, proposal=40, negotiation=70, won=100, lost=0)은 서비스 계층 책임
- opportunity가 won/lost로 마감되면 closed_at=now() 자동 기록
- sales_activity는 INSERT-only. UPDATE/DELETE 금지 (audit). occurred_at은 활동 시점 기준
- contact_person은 한 고객사(customer)에만 belong. customer 삭제 시 cascade
- 한 customer당 is_primary=true인 contact_person은 0~1개 (UI/서비스 계층 강제)
- lead·opportunity의 owner_user_id는 권한관리.app_user.id를 참조 — RBAC와 직결되어
  영업담당자 본인 데이터만 조회/수정 가능하도록 service guard 적용 (Stage 3)
- lead.owner_user_id는 set_null (담당자 퇴사 시 lead 보존),
  opportunity.owner_user_id는 restrict (활성 기회는 담당자 없이 둘 수 없음)
