# 알림

시스템 이벤트 → 사용자 통지 도메인. 채널(in-app/email/sms/push) 추상화, 템플릿 기반
본문 생성, 발송 시도/결과 RO 적재. 결재/주문/재고 등 모든 도메인의 비동기 통지를
이 도메인 단일 경로로 수렴시킨다.

## entities (시드)

### notification_template
```yaml
type: entity
name: notification_template
display: 알림 템플릿
domain: [알림]
table: notification_template
status: draft
pattern: D2
columns:
  - { name: id,                type: bigserial,    pk: true,  nullable: false }
  - { name: code,              type: varchar(80),  nullable: false, unique: true }  # APPROVAL_REQUESTED, ORDER_SHIPPED ...
  - { name: name,              type: varchar(150), nullable: false }
  - { name: event_type,        type: varchar(60),  nullable: false }   # 공통코드 EVENT_TYPE 참조
  - { name: channel,           type: varchar(20),  nullable: false }   # IN_APP/EMAIL/SMS/PUSH
  - { name: subject_template,  type: varchar(300), nullable: true }    # email/push 제목, in-app 헤더
  - { name: body_template,     type: text,         nullable: false }   # {{var}} placeholder 치환
  - { name: locale,            type: varchar(10),  nullable: false, default: 'ko-KR' }
  - { name: is_active,         type: boolean,      nullable: false, default: true }
  - { name: is_system,         type: boolean,      nullable: false, default: false }
  - { name: created_at,        type: timestamptz,  nullable: false, default: now() }
indexes:
  - { name: ix_notification_template_code,            columns: [code], unique: true }
  - { name: ix_notification_template_event_channel,   columns: [event_type, channel, locale] }
```

## rules (시드 비즈니스 규칙)
- `notification.status` 는 상태머신: PENDING → SENT → READ (또는 PENDING → FAILED). FAILED → PENDING 재시도는 새 log row 로 표현
- 발송은 비동기 워커가 `status=PENDING AND (scheduled_at IS NULL OR scheduled_at <= now())` 폴링하여 처리. 트랜잭션 안에서 발송 금지(외부 호출)
- `notification_template.body_template` 은 `{{var}}` 치환 컨벤션 — 미치환 placeholder 발견 시 발송 차단(빈 본문 방지)
- `notification_subscription.is_enabled=false` 인 (user, event_type, channel) 조합은 생성 자체를 skip — 발송 후 차단보다 비용 효율
- `notification_log` 는 RO append-only — 재시도/실패/제공자 응답 모두 신규 row. 마지막 시도 결과는 `notification.status` 에 반영
- 채널별 발송 우선순위: URGENT > HIGH > NORMAL > LOW — 워커 큐 정렬에 활용
- 결재 라인 PENDING 진입 / 주문 상태 변경 등 도메인 이벤트 → 이벤트 핸들러가 template lookup → notification insert. 도메인이 직접 외부 채널 호출 금지
- `event_type`, `channel`, `status`, `priority` 값은 [[공통코드]] 의 그룹(EVENT_TYPE, NOTIFY_CHANNEL, NOTIFY_STATUS, NOTIFY_PRIORITY) 참조 권장
- `recipient_id` 는 [[권한관리]] 의 app_user.id — 비활성 사용자에게는 신규 알림 생성 차단
- 보존 정책: SENT/READ 알림 90일, FAILED 30일 후 archive 잡에서 별도 보관 테이블로 이관 — 운영 DB 비대화 방지
